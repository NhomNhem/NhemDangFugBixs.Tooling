Design Document

v2.0.0 2026-05-29 Unity 2021.3+ VContainer 1.13+ C# 10 / Roslyn

Compile-time convention and reporting layer for VContainer in Unity. Attribute-driven registration, source-generated installers, scope marker architecture, and CLI preflight validation.

Core principle: Your architecture stays yours. Nhem DI makes it compile-time checked.

Architecture

Assembly layers

Nhem DI enforces a strict dependency direction across assembly boundaries.

Allowed:
  Application    → Shared
  Infrastructure → Shared
  Composition    → Shared
  Composition    → Application
  Composition    → Infrastructure

Forbidden:
  Application    → Composition   (NDF053)
  Infrastructure → Composition

Scope marker pattern

Services reference a conceptual scope marker — an interface in the Shared assembly. Composition maps that marker to a real VContainer LifetimeScope. This keeps Application/Domain layers independent from Unity composition.

Shared assembly
public interface IScopeMarker { }

public interface IGameplayScope
    : IScopeMarker { }

public interface IGameScope
    : IScopeMarker { }
Composition assembly
[LifetimeScopeFor<IGameplayScope>]
public sealed class
    GameplayLifetimeScope
    : LifetimeScope
{
  protected override void Configure(
      IContainerBuilder builder)
  {
    builder.RegisterGeneratedFor
        <IGameplayScope>();
  }
}

SG Coexistence

Nhem DI SG and VContainer SG run in parallel within the same compilation — no conflict since scan targets and output paths are completely different.

VContainer SGNhem DI SG
Scan target[Inject], constructor, Register* params[AutoRegisterIn], [LifetimeScopeFor]
Output__GeneratedInjector per typeScopeInstaller.g.cs per scope
PurposeAvoid reflection when resolvingAvoid manual boilerplate registration
Output pathVContainer/Generated/…Generated/NhemDI/…
ConflictNone — file path and attribute are completely different
When Nhem DI SG emits builder.Register<CombatCore>(), VContainer SG automatically picks up CombatCore and generates __GeneratedInjector for it. This is the desired behavior — the two SGs complement each other.

Attribute API

AttributeTargetVContainer emitPhase
[AutoRegisterIn<TScope>] Class builder.Register<T>(lifetime) Done
[AutoRegister] Class Register into default scope Done
[As<TInterface>] Class .As<TInterface>() chain Done
[EntryPoint] Class builder.RegisterEntryPoint<T>() Done
[LifetimeScopeFor<TScope>] LifetimeScope subclass Scope mapping — no code emit Done
[NhemManualFactory] Class Does not emit — only writes to report Phase 1
[NhemComponent(source)] MonoBehaviour builder.RegisterComponentInHierarchy<T>() etc. Phase 2

Installer — happy path

// <auto-generated />
// Nhem DI v2.0 — do not edit manually
// Scope:    IGameplayScope → GameplayLifetimeScope
// Services: 2  Components: 0  EntryPoints: 0  Manual: 1

using VContainer;
using GlassRefrain.Gameplay;

namespace GlassRefrain.Composition.Generated;

public static class GameplayScopeInstaller
{
    public static void RegisterGeneratedFor<IGameplayScope>(
        this IContainerBuilder builder)
    {
        // Ordered by dependency graph — not file order
        builder.Register<TargetContext>(Lifetime.Scoped)
               .As<ITargetContext>();

        builder.Register<CombatCore>(Lifetime.Scoped)
               .As<ICombatCore>();

        // M0MemoryState — SKIPPED: NDF025 primitive constructor
        // Register manually: builder.Register(_ => new M0MemoryState("id"), ...)
    }
}
Ordering rule: Generator sorts by dependency graph (topological sort), not by file scan order. TargetContext must emit before CombatCore because CombatCore depends on ITargetContext. This is why output must be snapshot tested.

Implement NDF025 — Primitive Constructor

File: Source~/DangFugBixs.Analyzers~/Rules/RegistrationGuardrailsRule.cs

Trigger condition

Class with [AutoRegisterIn] or [AutoRegister], constructor has at least one parameter of type string, int, float, double, bool, long, and class does not have [NhemManualFactory].

Implementation steps

  1. Define DiagnosticDescriptor in Diagnostics.cs 
    public static readonly DiagnosticDescriptor NDF025 =
    new(
        id: "NDF025",
        title: "Primitive constructor parameter",
        messageFormat: "{0} has primitive constructor parameter '{1} {2}' "
                     + "that cannot be resolved from the container. "
                     + "Add [NhemManualFactory] or use WithParameter.",
        category: "NhemDI.Registration",
        defaultSeverity: DiagnosticSeverity.Warning,
        isEnabledByDefault: true,
        helpLinkUri: "https://github.com/NhomNhem/NhemDangFugBixs.Tooling/wiki/NDF025"
    );
  2. Detect in RegisterSymbolAction — scan NamedType 
    context.RegisterSymbolAction(ctx =>
{
    var type = (INamedTypeSymbol)ctx.Symbol;

    // Skip if no AutoRegister*
    if (!HasAutoRegisterAttribute(type)) return;

    // Skip if already marked NhemManualFactory
    if (HasManualFactoryAttribute(type)) return;

    // Find public/internal constructor
    var ctor = type.Constructors
        .Where(c => c.DeclaredAccessibility
            is Accessibility.Public
            or Accessibility.Internal)
        .OrderByDescending(c => c.Parameters.Length)
        .FirstOrDefault();

    if (ctor == null) return;

    foreach (var param in ctor.Parameters)
    {
        if (IsPrimitiveType(param.Type))
        {
            ctx.ReportDiagnostic(Diagnostic.Create(
                NDF025,
                type.Locations[0],
                type.Name,
                param.Type.Name,
                param.Name));
        }
    }
}, SymbolKind.NamedType);

// Helper
private static bool IsPrimitiveType(ITypeSymbol type) =>
    type.SpecialType is
        SpecialType.System_String or
        SpecialType.System_Int32  or
        SpecialType.System_Single or
        SpecialType.System_Double or
        SpecialType.System_Boolean or
        SpecialType.System_Int64;
  3. Skip in generator — do not emit types with NDF025 
    // In RegistrationEmitter.cs
private bool ShouldSkipRegistration(INamedTypeSymbol type)
{
    if (HasManualFactoryAttribute(type)) return true;

    var ctor = GetPrimaryConstructor(type);
    if (ctor != null && ctor.Parameters.Any(p => IsPrimitiveType(p.Type)))
        return true;

    return false;
}

// In emit loop — add comment to generated file
if (ShouldSkipRegistration(service))
{
    writer.WriteLine(
        $"// {service.Name} — SKIPPED: NDF025 primitive constructor");
    writer.WriteLine(
        $"// Register manually in Configure()");
    continue;
}
  4. Emit into Report section "Manual factories required" 
    // In ReportEmitter.cs
writer.WriteLine("## Manual Factories Required");
foreach (var skipped in skippedServices)
{
    writer.WriteLine($"### {skipped.TypeName}");
    writer.WriteLine($"Reason: {skipped.SkipReason}");
    writer.WriteLine();
    writer.WriteLine("Recommended registration:");
    writer.WriteLine("```csharp");
    writer.WriteLine(skipped.GenerateSnippet());
    writer.WriteLine("```");
}

Implement NDFG014 — Orphan Service

File: Source~/DangFugBixs.Analyzers~/Rules/ArchitectureGuardrailsRule.cs
Context: RegisterCompilationEndAction — after all symbols have been scanned

Problem

Service has [AutoRegisterIn<IGameplayScope>] but no [LifetimeScopeFor<IGameplayScope>] exists in the entire compilation. Service compiles fine, no runtime error — it simply never gets registered. This is the most dangerous silent failure.

Implementation steps

  1. Define DiagnosticDescriptor 
    public static readonly DiagnosticDescriptor NDFG014 =
    new(
        id: "NDFG014",
        title: "Orphan service — no composition target",
        messageFormat: "{0} is registered for scope {1} but no "
                     + "[LifetimeScopeFor<{1}>] was found. "
                     + "This service will never be registered at runtime.",
        category: "NhemDI.ScopeMapping",
        defaultSeverity: DiagnosticSeverity.Error,
        isEnabledByDefault: true
    );
  2. Collect in CompilationEndAction 
    compilationEnd.RegisterCompilationEndAction(endCtx =>
{
    // Already have: CollectScopeMappings() returns
    // Dictionary<scopeMarkerFQN, List<LifetimeScopeSymbol>>
    var scopeMappings = CollectScopeMappings(endCtx.Compilation);

    // NDFG014: cross-check autoRegistered list
    foreach (var (serviceType, scopeMarkerFQN)
        in autoRegisteredTypes)
    {
        if (!scopeMappings.ContainsKey(scopeMarkerFQN))
        {
            endCtx.ReportDiagnostic(Diagnostic.Create(
                NDFG014,
                serviceType.Locations[0],
                serviceType.Name,
                scopeMarkerFQN));
        }
    }
});
  3. autoRegisteredTypes must store scope FQN 
    // In RegisterSymbolAction — collect scope FQN as well
var autoRegAttr = type.GetAttributes()
    .FirstOrDefault(a => IsAutoRegisterInAttribute(a));

if (autoRegAttr != null)
{
    var scopeTypeArg = autoRegAttr.AttributeClass?
        .TypeArguments.FirstOrDefault();

    if (scopeTypeArg != null)
    {
        // ConcurrentBag<(INamedTypeSymbol type, string scopeFQN)>
        autoRegisteredTypes.Add(
            (type, scopeTypeArg.ToDisplayString()));
    }
}
  4. Performance: early exit if no autoRegistered types 
    // Top of CompilationEndAction
if (autoRegisteredTypes.IsEmpty) return;

// Collect scope mappings ONLY when needed
var scopeMappings = CollectScopeMappings(endCtx.Compilation);

Implement RegisterGeneratedFor<T>

File: Source~/DangFugBixs.Generators~/VContainerAutoRegisterGenerator.cs

Extension method pattern

Generator produces an extension method instead of a partial class. User calls builder.RegisterGeneratedFor<IGameplayScope>() in their Configure() — full control over ordering and manual registration.

Incremental pipeline

  1. Step 1: Collect scope markers — cached, rarely changes 
    var scopeMarkers = context.SyntaxProvider
    .ForAttributeWithMetadataName(
        "NhemDangFugBixs.Attributes.LifetimeScopeForAttribute`1",
        predicate: (node, _) => node is ClassDeclarationSyntax,
        transform: (ctx, _) => ExtractScopeMarkerInfo(ctx))
    .Where(x => x != null)
    .Collect();
  2. Step 2: Collect services — incremental per file 
    var services = context.SyntaxProvider
    .ForAttributeWithMetadataName(
        "NhemDangFugBixs.Attributes.AutoRegisterInAttribute`1",
        predicate: (node, _) => node is ClassDeclarationSyntax,
        transform: (ctx, _) => ExtractServiceInfo(ctx))
    .Where(x => x != null && !x.ShouldSkip)
    .Collect();
  3. Step 3: Combine and emit per scope 
    context.RegisterSourceOutput(
    scopeMarkers.Combine(services),
    (spc, combined) =>
    {
        var (markers, allServices) = combined;

        foreach (var marker in markers)
        {
            var scopeServices = allServices
                .Where(s => s.ScopeFQN == marker.ScopeFQN)
                .OrderByDependencyGraph()  // topological sort
                .ToList();

            var source = EmitInstaller(marker, scopeServices);
            spc.AddSource(
                $"{marker.Namespace}.{marker.ScopeName}Installer.g.cs",
                source);
        }
    });

File: DangFugBixs.Tests/GeneratedOutputSnapshotTests.cs

Snapshot test ensures generated output is deterministic — does not change between compile runs when input is unchanged.

[Test]
public async Task Snapshot_HappyPath_GameplayScope()
{
    var result = await GeneratorTestHost.RunAsync("""
        [AutoRegisterIn<IGameplayScope>(Lifetime = NhemLifetime.Scoped)]
        [As<ITargetContext>]
        public class TargetContext : ITargetContext { }

        [AutoRegisterIn<IGameplayScope>(Lifetime = NhemLifetime.Scoped)]
        [As<ICombatCore>]
        public class CombatCore : ICombatCore
        {
            public CombatCore(ITargetContext target) { }
        }

        [LifetimeScopeFor<IGameplayScope>]
        public class GameplayLifetimeScope : LifetimeScope { }
        public interface IGameplayScope : IScopeMarker { }
        """);

    // Verify ordering: TargetContext before CombatCore
    Assert.That(result.GeneratedSource,
        Does.Contain("Register<TargetContext>"));

    var targetIdx = result.GeneratedSource.IndexOf("Register<TargetContext>");
    var combatIdx = result.GeneratedSource.IndexOf("Register<CombatCore>");
    Assert.That(targetIdx, Is.LessThan(combatIdx));

    // Snapshot compare full output
    await Verify(result.GeneratedSource)
        .UseFileName("GameplayScope_HappyPath");
}

    GameLifetimeScope

NDF026 · Info — BackendConfig constructor param
TinyRiftBackendClient has a ScriptableObject-derived constructor parameter BackendConfig config. Ensure it is registered with builder.RegisterInstance(config).AsSelf() before calling RegisterGeneratedFor.
