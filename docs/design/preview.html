Scope Marker Architecture

Services reference conceptual scope markers in Shared/Application assemblies. Composition maps those markers to a real VContainer LifetimeScope. This prevents Domain/Application assemblies from referencing Unity composition classes.

Shared assembly

public interface IScopeMarker
{
}

public interface IGameplayScope : IScopeMarker
{
}

Application assembly

[AutoRegisterIn<IGameplayScope>(Lifetime = NhemLifetime.Scoped)]
[As<ICombatCore>]
public sealed class CombatCore : ICombatCore
{
}

Composition assembly

[LifetimeScopeFor<IGameplayScope>]
public sealed class GameplayLifetimeScope : LifetimeScope
{
    protected override void Configure(IContainerBuilder builder)
    {
        // Manual registrations first when needed.
        builder.RegisterInstance(_settings).AsSelf();

        // Generated registrations for this scope.
        builder.RegisterGeneratedFor<IGameplayScope>();
    }
}

Correct RegisterGeneratedFor<T> Shape

The generated extension method must use a generic type parameter. Do not write invalid hardcoded generic method declarations like RegisterGeneratedFor<IGameplayScope>(this IContainerBuilder builder).

Wrong pseudo-code

public static void RegisterGeneratedFor<IGameplayScope>(
    this IContainerBuilder builder)
{
    // invalid generic method syntax
}

Correct pattern

public static void RegisterGeneratedFor<TScope>(
    this IContainerBuilder builder)
    where TScope : IScopeMarker
{
    if (typeof(TScope) == typeof(IGameplayScope))
    {
        RegisterGameplayScope(builder);
        return;
    }

    throw new InvalidOperationException(
        $"No generated registrations for {typeof(TScope).FullName}");
}

private static void RegisterGameplayScope(IContainerBuilder builder)
{
    builder.Register<CombatCore>(Lifetime.Scoped)
           .As<ICombatCore>();
}

Unity Package Layout Decision

Use hybrid packaging. Runtime and Attributes are source + asmdef. Analyzer/source generator is DLL-only. Do not ship runtime DLLs next to runtime asmdefs.

Keep

Runtime/**/*.cs
Runtime/**/*.asmdef
Runtime/**/*.meta

Editor/**/*.cs
Editor/**/*.asmdef
Editor/**/*.meta

Analyzers/**/*.dll
Analyzers/**/*.dll.meta

Exclude

Runtime/**/*.dll
Runtime/**/*.dll.meta
Runtime/Attributes/**/*.dll
Runtime/Attributes/**/*.dll.meta

Analyzers/**/*.asmdef
Analyzers/**/*.asmdef.meta

Asmdef references

Editor asmdef must reference the Runtime/Attributes asmdefs if Editor code uses those namespaces. GR consuming asmdefs should reference package Runtime/Attributes asmdefs, not runtime DLLs.

Slice 1 — ManualFactory Contract

ManualFactory is a marker that says: this type is intentionally not emitted as a normal generated registration because it requires authored values, WithParameter, RegisterInstance, or a custom factory.

Naming decision required

Because the current API uses concise names, prefer [ManualFactory]. Use [NhemManualFactory] only if approved as an explicit exception.

[AttributeUsage(AttributeTargets.Class, AllowMultiple = false, Inherited = false)]
public sealed class ManualFactoryAttribute : Attribute
{
    public string? Reason { get; init; }
}
[ManualFactory(Reason = "Requires authored memoryId.")]
[AutoRegisterIn<IGameplayScope>(Lifetime = NhemLifetime.Singleton)]
[As<IMemoryState>]
public sealed class MemoryState : IMemoryState
{
    public MemoryState(string memoryId)
    {
    }
}

Slice 2 — NDF025 Primitive Constructor Parameters

Detect services that cannot be safely generated because their constructor needs primitive authored values such as string, int, float, bool, long, or double.

Problem

[AutoRegisterIn<IGameplayScope>(Lifetime = NhemLifetime.Singleton)]
public sealed class MemoryState : IMemoryState
{
    public MemoryState(string memoryId)
    {
    }
}

The container cannot know which string to inject.

Expected fix

[ManualFactory(Reason = "Requires authored memoryId.")]
[AutoRegisterIn<IGameplayScope>(Lifetime = NhemLifetime.Singleton)]
public sealed class MemoryState : IMemoryState
{
    public MemoryState(string memoryId)
    {
    }
}

// In LifetimeScope.Configure:
builder.Register(_ => new MemoryState("M0RevealCandidate"),
    Lifetime.Singleton).As<IMemoryState>();

Recommended behavior

  • AutoRegister + primitive constructor + no ManualFactory: emit NDF025.
  • AutoRegister + primitive constructor + ManualFactory: no NDF025 warning.
  • ManualFactory types should not be emitted as normal Register<T> registrations.
  • Generated output/report should include a manual registration hint.

Slice 3 — NDF026 ScriptableObject External Instance Hint

ScriptableObject dependencies are authored Unity assets and should be registered manually using RegisterInstance.

Service

[AutoRegisterIn<IGameScope>(Lifetime = NhemLifetime.Singleton)]
[As<IBackendClient>]
public sealed class BackendClient : IBackendClient
{
    public BackendClient(BackendConfig config)
    {
    }
}

Composition

[SerializeField] private BackendConfig _config;

protected override void Configure(IContainerBuilder builder)
{
    builder.RegisterInstance(_config).AsSelf();
    builder.RegisterGeneratedFor<IGameScope>();
}

Rule

NDF026 should be Info/report hint by default. It should not auto-register ScriptableObject assets and should not block if the user has already registered the instance manually.

Slice 4 — NDFG014 Orphan Service

A service targeting a scope with no composition target will silently never be registered. This should be detected, but carefully to avoid cross-assembly false positives.

Implementation decision

Implement authoritative NDFG014-style validation in di-smoke first, because di-smoke sees built assemblies. Compile-time analyzer can be added later with conservative false-positive rules.

Required data model

public readonly record struct AutoRegisteredServiceInfo(
    INamedTypeSymbol Type,
    string ScopeFqn,
    Location? Location);

Insufficient

var autoRegistered = new List<INamedTypeSymbol>();

This loses the target scope FQN.

Required

var autoRegistered =
    new ConcurrentBag<AutoRegisteredServiceInfo>();

This keeps type, scope, and location for diagnostics.
