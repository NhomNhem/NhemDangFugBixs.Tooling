Issues Found

NDF022 False Positive on Public [Inject] Methods

Analyzer warned for public void Construct([Inject]) even though this pattern is fully compatible with the VContainer Source Generator. Only private [Inject] methods are incompatible.

  • Impact: Spam warnings in every GR project using public injection.
  • Root Cause: Condition checked Accessibility.Public instead of Accessibility.Private.
NDFG010 False Positive on Referenced Assembly Markers

When [LifetimeScopeFor] was defined in a referenced assembly (e.g. NhemDangFugBixs.Attributes package), NDFG010 reported "missing mapping" because the analyzer only scanned source types.

  • Impact: Error on every [AutoRegisterIn(typeof(IGameplayScope))] registration even though the marker existed in the Attributes package.
  • Root Cause: RegisterSymbolAction(SymbolKind.NamedType) only fires for types in the current compilation's source files, not referenced assemblies.
UPM Packaging DLL/Asmdef Filename Collision

Unity warned when both .asmdef and .dll shared the same assembly name. Runtime and Attributes were shipped as precompiled DLLs with matching asmdef names.

  • Impact: Unity console warnings on package import.
  • Root Cause: Package included both precompiled DLLs and asmdef files for the same assembly names.

Fix 2 — NDFG010: Full Compilation Scan

Replaced inline LifetimeScopeFor collection inside RegisterSymbolAction with a dedicated CollectScopeMappings() method that walks the entire Compilation.GlobalNamespace, including types from referenced assemblies.

private static Dictionary<string, List<INamedTypeSymbol>> CollectScopeMappings(Compilation compilation) {
    var result = new Dictionary<string, List<INamedTypeSymbol>>();
    foreach (var type in GetAllNamedTypes(compilation.GlobalNamespace)) {
        // scans ALL assemblies, not just source
    }
    return result;
}

How to Use

1. Install via UPM (Git URL)

https://github.com/<user>/NhemDangFugBixs.Tooling.git

Runtime and Attributes compile as source; Analyzers attach automatically via NhemDangFugBixs.Analyzers.dll in the Analyzers/ folder.

2. Register a Service

using NhemDangFugBixs.Attributes;

[AutoRegisterIn(typeof(IGameplayScope), Lifetime = NhemLifetime.Scoped)]
public class PlayerService { }

3. Define a Scope Marker

[LifetimeScopeFor(typeof(IGameplayScope))]
public class GameplayLifetimeScope : LifetimeScope { }

public interface IGameplayScope { }

Place [LifetimeScopeFor] in any assembly — the analyzer will find it even if it lives in a referenced package.

Recommendations

CI Automate Analyzer DLL Build

Current workflow requires manual dotnet build -c Release and copying the DLL. Add a GitHub Actions step that builds the analyzer and commits the updated DLL to the deployment branch automatically.

DevEx Auto-Sync Source to Runtime Folder

When editing Source~/DangFugBixs.Attributes~/Attributes/*.cs, developers must remember to copy changes to Runtime/Attributes/. An MSBuild target or a pre-commit hook can enforce this automatically.

Testing Cross-Compilation Integration Tests

Current unit tests run in a single compilation. Add a test that simulates two compilations (Project GR + Package Attributes) where [LifetimeScopeFor] lives in the package assembly to prevent regression of NDFG010.

Config .editorconfig Support for NDF022

Some teams may prefer internal as the minimum accessibility. Expose an editorconfig option so users can configure the threshold without forking the analyzer.

dotnet_diagnostic.NDF022.minimum_accessibility = public   # or internal, private
Performance Reduce Compilation Scan Overhead

CollectScopeMappings() iterates every type in every referenced assembly. For large projects this is acceptable today, but for teams with 500+ source files it may become noticeable. Consider caching or using Compilation.GetSymbolsWithName() in the future.
