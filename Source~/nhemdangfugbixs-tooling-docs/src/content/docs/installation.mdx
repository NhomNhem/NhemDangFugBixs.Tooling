## Requirements

| Requirement | Notes |
|---|---|
| Unity | 2021.3+ |
| VContainer | Required by the composition asmdef |
| asmdef usage | Recommended for layered architecture |
| .NET SDK | Needed only if you run CLI or source projects locally |

## Install from Git URL (UPM)

In Unity Package Manager:

1. Open `Window > Package Manager`.
2. Click `+` -> `Add package from git URL...`.
3. Use the repository URL for this package.

## Install via `manifest.json`

Add dependency entries to your Unity project manifest:

```json
{
  "dependencies": {
    "jp.hadashikick.vcontainer": "https://github.com/hadashiA/VContainer.git?path=VContainer/Assets/VContainer#1.17.0",
    "com.nhemdangfugbixs.tooling": "https://github.com/NhomNhem/NhemDangFugBixs.Tooling.git?path=/&branch=deploy"
  }
}
```

## Recommended asmdef direction

- `Shared` contains scope markers and service contracts.
- `Gameplay` or `Application` contains services with `[AutoRegisterIn]` and package attributes.
- `Gameplay` or `Application` does not need a `VContainer` reference just to declare DI intent.
- `Composition` contains `[LifetimeScopeFor]`, references `VContainer`, and references the service assemblies it wants to compose.

## Verify installation

1. Confirm package attributes are visible in a service asmdef.
2. Create one minimal `[AutoRegisterIn<TScope>]` service.
3. Create one `[LifetimeScopeFor<TScope>]` mapping in a composition asmdef.
4. Confirm the composition assembly can call `builder.RegisterGeneratedFor<TScope>()`.
5. Run `di-smoke preflight` if the CLI is available.

## Discovery boundary (MVP)

Generated composition installers discover registrations from:

1. the current compilation
2. directly referenced assemblies only

The generator does not scan all loaded Unity assemblies and does not perform transitive discovery in the MVP path.
