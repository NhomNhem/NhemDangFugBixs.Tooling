description: Register services by conceptual scope markers instead of concrete LifetimeScope classes.

Use scope markers to avoid architecture inversion across asmdef layers.

## The problem

If a service assembly uses a concrete composition type such as:

```csharp
[AutoRegisterIn(typeof(GameplayLifetimeScope))]
```

it now depends on Composition. That breaks clean layering.

## Recommended pattern

Define markers in a shared low-level assembly:

```csharp
namespace Game.Shared.Composition;

public interface IScopeMarker { }
public interface IProjectScope : IScopeMarker { }
public interface IGameplayScope : IScopeMarker { }
```

Use the marker in services:

```csharp
[AutoRegisterIn<IGameplayScope>(Lifetime = NhemLifetime.Scoped)]
[As<IPhaseStateMachine>]
public sealed class PhaseStateMachine : IPhaseStateMachine { }
```

This service assembly can stay free of direct `VContainer` references.

Map the marker to a real scope in Composition only:

```csharp
using NhemDangFugBixs.VContainer;
using VContainer;
using VContainer.Unity;

[LifetimeScopeFor<IGameplayScope>]
public sealed class GameplayLifetimeScope : LifetimeScope
{
    protected override void Configure(IContainerBuilder builder)
    {
        builder.RegisterGeneratedFor<IGameplayScope>();
    }
}
```

## Composition-only generation

Assemblies that contain `[LifetimeScopeFor]` are composition targets.

Only those assemblies emit:

- `NhemGeneratedVContainerExtensions`
- `RegisterGeneratedFor<TScope>()`
- one stateless installer per mapped scope

MVP discovery inspects:

1. the current compilation
2. directly referenced assemblies only

It does not scan all loaded Unity assemblies and does not use transitive discovery yet.

## Dependency direction

Good:

```txt
Application -> Shared
Infrastructure -> Shared
Composition -> Application + Infrastructure + Shared + VContainer
```

Avoid:

```txt
Application -> Composition
```

## Common mistakes

- Defining marker interfaces inside a composition assembly.
- Mapping one marker to multiple `LifetimeScope` classes in the same composition compilation.
- Forgetting `using NhemDangFugBixs.VContainer;` where `RegisterGeneratedFor<TScope>()` is called.
- Expecting an unreferenced service asmdef to be discovered automatically.
