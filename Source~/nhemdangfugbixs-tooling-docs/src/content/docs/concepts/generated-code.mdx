The generator is designed for readable output, not hidden runtime magic.

## Generated Installer API

```csharp
builder.RegisterGeneratedFor<IGameplayScope>();
```

Generated code should resemble handwritten VContainer registration.

## Typical Output Shape

- Service registrations (`Register<T>(Lifetime...)`)
- Contract bindings (`As<TContract>()`, optional `AsSelf()`)
- Entry points (`RegisterEntryPoint<T>(Lifetime)`)
- Scene components (`RegisterComponentInHierarchy<T>()` when requested)
- Optional MessagePipe broker registrations

## Emission Behavior

1. Map scope marker to owner `LifetimeScope`.
2. Gather attributed services matching that marker.
3. Validate and deduplicate.
4. Emit stable installer code and optional report metadata.

In 8.0, every `[LifetimeScopeFor<TScope>]` mapping emits a generated route. If no services are discovered for the marker, the generated installer is a no-op so `builder.RegisterGeneratedFor<TScope>()` stays available and deterministic.

Composition files that call generated routes need the extension namespace:

```csharp
using NhemDangFugBixs.VContainer;
```

## Debugging Tips

- Confirm marker mapping exists via `[LifetimeScopeFor]`.
- Confirm service assembly references runtime attributes assembly.
- Confirm the composition assembly references the service assemblies it should compose.
- Check diagnostics in [Reference: Diagnostics](/NhemDangFugBixs.Tooling/docs/reference/diagnostics/).
